Understanding the Problem

Designing AI experiences, with AI tools, on shifting ground

Designers now work on two fronts at once. They design for AI, shaping how people interact with assistants, and with AI, using generative tools to explore and produce faster. At Dassault Systèmes' DELMIA, both fronts met in a single project: producing Virtual Companion mockups for the COMEX, with almost nothing stable to build on.

🚫

Can't Validate

No access to end users. No interviews or tests to check my choices.

⏱️

Can't Wait

The COMEX mockups had deadlines, and the topic kept moving while we worked.

📋

Can't Rely on the Reference

Existing guidelines were incomplete, still evolving, and mixed up notions like assistant, agent and skill.

Context

DELMIA, one of Dassault Systèmes' brands, covers industrial operations. The project sits within GEN7, the group's shift toward the generative economy, which includes the Virtual Companion (the platform's AI assistant) and Generative Experiences (AI-assisted design).

I wasn't attached to one product. My mission was to build resources the whole UX team could reuse: guidelines, components, evaluation methods and experiments. My users were the designers themselves.

Research Phase

📂 Documentation Audit

Centralizing guidelines and resources scattered across several spaces.

🗺️ Journeys & User Stories

Rebuilding the main journeys, organized around usage situations and intentions rather than a list of components, and linked to mockups, usability issues, positive points and open questions.

⚖️ Heuristic Benchmark

Comparing Claude, ChatGPT, Mistral, Gemini, Notion and the internal assistant AURA, with a grid built from research on trust in intelligent systems, UX heuristics for generative AI and industry publications. The goal: identify conventions and friction points, not crown a winner.

🔍 Comparative UI Audit

Observing how each interface lets users consult, understand and manipulate the responses it produces.

With no access to users, I studied the experiences they already know. It doesn't replace user research, but it gave me informed hypotheses instead of intuition.

Key Findings

Completeness

Some situations simply weren't documented.

→ Recommendations had to be built, not just collected.

Stability

Guidelines and components were still changing.

→ Resources must be designed as living, not frozen.

Vocabulary

Assistant, agent, skill and Virtual Companion were used interchangeably.

→ They imply different levels of autonomy, so different UX stakes.

Relationships

The same component appeared in several contexts with no explicit link.

→ Each component's scope of use needed to be made clear.

Concept & Approach

Two tracks, one framework

I couldn't wait for the reference to stabilize, and I wouldn't invent recommendations from intuition. So I ran two tracks in parallel.

🎨 Designing for AI

Structure the experience: guidelines by usage situation, and a GEN7 component library that separates component, composition and template, with properties and variants covering many states without multiplying components.

🤖 Designing with AI

Understand when generative tools genuinely help, by testing them instead of assuming.

Experimenting with AI

What does an agent need to build an interface correctly?

A first experiment with Figma Make compared the same interface built with and without AI. It showed a limit quickly: the tool could take inspiration from a library but couldn't use its components, only reproduce them. Comparing production time told me nothing about quality.

So I changed the question: which information in our Design System lets an agent produce an interface correctly? I built a targeted experiment with the Figma Design Agent on the Tree View component, varying the level of documentation and the presence of a usage example.

Results

0.75

Exploratory results, three runs per condition. Most of the gain comes from adding minimal documentation.

📈 Documentation makes the agent predictable

Detailing every variant barely moves the score, but makes results far more consistent.

🔒 A ceiling the documentation can't lift

For choosing the right link variant by position in the tree, the agent activated the right property but always picked "middle child". That's a limit of the agent, not a gap in the Design System.

📐 An example gives a shape, not a logic

It didn't improve configuration accuracy, but tree depth and fill-container sizing were always reached when an example was present.

How we structure design resources directly shapes what AI can do with them.

Putting It to the Test: Generate Process

A real project where both tracks meet

The brief: design a flow that extracts, from a PDF of up to a hundred pages, the information needed to generate an industrial process linked to an mBOM. Two to three weeks to scope and mock up, with no access to end users.

  • →

    I built the user flow for what could realistically be developed in that timeframe.

  • →

    I used the Figma Design Agent to explore several wireframe directions quickly, giving it a need, constraints and structured design resources.

  • →

    Its proposals were material to explore, sort and rework, not a finished mockup.

The guidelines and library gave the AI a framework, and the AI became a faster way to explore that framework.

We chose to deliver a realistic version with current resources, and to document the ideal journey separately, notably cross-consulting the source document and the extracted process.

Results, Limits & Next Steps

✅ What Worked

  • Guidelines and components directly reusable in real projects.
  • AI that speeds up exploration, as long as it's well framed and well fed.

⚠️ Limits

  • No direct access to end users: recommendations remain partly hypotheses, even when informed by the benchmark.
  • Tools evolve fast, so some results and benchmarks age quickly.
  • Classic UX tools struggle when part of the reasoning is done by AI: showing only the user's actions is no longer enough.

🔭 Next Steps

  • Evolve the Design System toward documentation agents can use.
  • Continue experimenting by crossing documentation and examples.
  • Turn the benchmark into a living, versioned reference.

Where This Leads:
A Queryable Design System

Design resources don't only serve designers. They also condition how well agents can produce. That points to a Design System an agent can query: answering a designer's questions about components and guidelines, and auditing a mockup to flag deviations.

I didn't build this during the six months. It's the direction the work points to.

Facing AI, the challenge isn't only learning new tools. It's structuring the design knowledge that lets both designers and agents use them well.
